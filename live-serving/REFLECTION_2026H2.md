# 2026 下半年同方向项目扫描与自我反思

扫描对象：MLSys 2026、EuroSys 2026、PCDS 2026 的 KV 缓存项目，以及 GitHub 上活跃的 serving 基础设施。结论一句话：**淘汰算法这条赛道已经被占满，“选哪个淘汰器”不再是前沿问题；我们唯一还站得住的主张是窗口判据与机制诊断，而前沿已经转到粒度与拓扑。**

## 一、同方向项目地图

| 项目 | 出处 | 做什么 | 与我们的关系 |
|---|---|---|---|
| SkipKV | MLSys'26（Intel Labs / USC），2026-10 vLLM 集成 | 句级 KV 淘汰+跳过生成，针对长 CoT 推理模型 | 不同层：decode 期 token/sentence 级压缩，不涉 prefix 块淘汰 |
| Kitty | MLSys'26 | 2-bit KV 量化（通道级动态提精度） | 不同层：量化，与淘汰正交 |
| FlexiCache | MLSys'26，基于 vLLM | 按注意力头的时间稳定性做 GPU/主机分层放置 | 同栈不同层：页级放置，可作为我们的集成点/基线 |
| OPKV | MLSys'26 | paged KV 的可召回稀疏性 | 部分重叠：块内稀疏，我们管块间取舍 |
| Adaptive KV Caching | EuroSys'26 | 容量自适应 KV 缓存 | 直接重叠：这正是我们 κ 轴在做的事 |
| When Fancy Eviction Fails | arXiv 2609.28870（清华/哈佛/CMU，含 SIEVE 作者 J. Yang） | 20B token 生产 trace、14 种淘汰算法，结论 LRU 稳健 + 三条原则（quick demotion / compute-aware / capacity-adaptive 粒度） | **正面对撞**：我们的结论必须与它对齐 |
| Prefix-Route | PCDS 2026 | 增长型前缀 + 有限缓存下的“淘汰感知路由”，8 种路由策略 + trace 模拟器 | 相邻：把淘汰与多副本路由耦合，正是我们说的 2028 方向 |
| Mooncake / LMCache / aibrix / Dynamo | 生产基础设施 | KVCache 分层、offload、disaggregated prefill | 我们实验缺的拓扑就是这里 |

## 二、那篇论文对我们三个结论的冲击

1. **“SIEVE 比 LRU 高 24.6%” vs “LRU 稳健”**——两者都对，但成立条件不同：生产 trace 的复用集中在极短间隔内，recency 是极强预测器；我们的 conversation 负载是“会话步进 + 多请求交错”，同一链在被反复复用却一直被新请求挤到队尾，recency 失效。差异来自**复用间隔分布**，而这正是我们 σ/κ 判据的块级代理。这给了我们一个比“某策略更强”更硬的命题：**同一算法在两份负载上给出相反排序，是因为窗口位置不同**。
2. **compute-aware eviction 我们其实早就在测**：我们的 DEPTH（越深越先淘汰 = 失效的注意力计算越少）就是它的粗粒度版，且实测在 toolagent 上排第二。他们把它做到 partial-node（token 级部分块）才拿到 19.9% TTFT 与 18.8% prefill 吞吐——说明**block 粒度已经到顶**，这与我们 agentic 上 0.8% 跨度的结论是同一件事的两面。
3. **quick demotion（丢一次性前缀）**：用我们的 ACCESS 计数器即可实现。本轮据此新增 CTW（一次性命中优先丢弃 + 深度作为代价）：

| 负载 | LRU | SIEVE | DEPTH | LFU-W | **CTW（本轮新增）** |
|---|---|---|---|---|---|
| synthetic | 0.0513 | 0.0490 | 0.0518 | 0.0513 | 0.0511 |
| conversation | 0.1073 | **0.1337** | 0.1313 | 0.1314 | 0.1319 |
| toolagent | 0.4167 | 0.4247 | 0.4384 | **0.4409** | 0.4406 |
| agentic | 0.6378 | 0.6342 | 0.6390 | 0.6390 | 0.6390 |
| 四负载均值 | 0.3033 | 0.3104 | 0.3151 | **0.3157** | **0.3157** |

**CTW 与 LFU-W 的四负载均值完全相同（0.3157）**，per-regime 剖面互有胜负（CTW 在 conversation 高 0.0005，在 toolagent 低 0.0003）。两个来自不同原则家族的机制收敛到同一点——这就是本轮最重要的反思结论：**受害者的“选择原则”已经饱和，剩余空间不在原则里。**

## 三、Novelty 审计：我们能主张什么，不能主张什么

**不能主张**：新的 SOTA 淘汰器。14 算法 × 20B token 的研究 + 三条原则 + MLSys'26 上四篇 KV 系统，已经把这条赛道封住；再报一个“我比 SIEVE 高 x%”会被直接判为不可迁移。

**可以主张**（且已被自己的数据支撑）：

1. **窗口判据的实测标定**：σ（共享覆盖率）倒 U、κ（容量/工作集）单调，两端效应趋零、中间最大（24.6%）。它同时解释了两份互相矛盾的文献，而不是与之竞争。
2. **机制诊断型负结果**：块级树信号不存在（分支度 0.001–0.002）、准入侧门控在本栈零触发（500 次判定 0 推迟）、吞吐在共享卡上不可归因（同配置跨度 27%）。这类结论在顶会论文里通常被省略，但对后来者最有用。
3. **可复现装置**：同机 110 轮、8 类淘汰器、4 个 regime、逐轮原始 JSON + 一键复现脚本。

对应的体裁就是 ReScience C 的 `[Re]`（零费用订阅制），或 TMLR 的 replication/negative-results 通道——与“只走零费用”的约束一致。

## 四、下一步（按性价比排序，都不需要新硬件）

- **A（零 GPU 成本，最高优先）**：用 2609.28870 公开的 20B-token traces + 模拟器，在中立第三方负载上检验我们的窗口律——若 σ/κ 判据在他们的生产 trace 上也能预测“何时策略有效”，我们的主张就从“合成负载的观察”升级为“跨负载的定律”。纯 CPU，几小时量级。
- **B（署名路径）**：向 FlexiCache（vLLM 基座）或 vLLM 官方 APC 提 PR，把 LFU-W/CTW 作为可选 evictor 与我们的四 regime 回归装置一起提交。这是目前唯一能拿到真实 credit 的低风险动作，且与我们的代码完全兼容。
- **C（需新拓扑）**：disaggregated prefill 下的准入×淘汰联合优化——Prefix-Route 已在这条路上，我们缺的是机器。

## 五、一句话总结

这台机器能榨出的结论已经榨干：**淘汰原则饱和、块级粒度到顶、准入在单机无落点**。26/27/28 的前沿在 token 级粒度与 disaggregated 拓扑，而我们在那里目前只有判据、没有数据。要么用公开 trace 把判据验证成定律，要么进别人的代码库换取署名——这两条是现在唯一还能推进的路。
