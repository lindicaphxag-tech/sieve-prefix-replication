# F1 策略收益是窗口的函数，不是策略的函数

| 负载 | 共享强度 σ | 命中率跨度 | 最优 |
|---|---|---|---|
| synthetic | ~0（每请求独立） | 0.0449–0.0518（4.5%） | DEPTH / LRU |
| conversation | 中（前缀整链复用） | 0.1073–0.1337（**24.6%**） | SIEVE |
| toolagent | 高（家族共享） | 0.4167–0.4409（5.8%） | **LFU-W** |
| agentic | 极高（65% 长度共享） | 0.6342–0.6390（0.8%） | 基本无差别 |

同一批策略，在 conversation 里 SIEVE 领先 LRU 24.6%，在 agentic 里五策略差 0.8%。原因不是策略失效，而是**共享主干被在跑请求的引用计数钉住**（refcount>0 的块根本不进淘汰候选集），淘汰器无从干预。

容量维度同理且更单纯：400 blocks 时 SIEVE 仅领先 2.6%（0.0722 / 0.0740），800 时几乎持平（0.0783 / 0.0785），1200 时 +6.6%（0.0813 / 0.0866），1733 时 +24.6%（0.1073 / 0.1337）。

**推论**：任何“更好的淘汰器”论文若不报告 σ 与 κ（容量/工作集比），其结论都无法迁移。这是 2026 之后该子领域必须补的口径。

# 4. 框架 WVC（定稿）

**W1 窗口判据（调度器侧）**：σ（共享覆盖率）轴为倒 U，中间最大；κ（容量/工作集）轴单调递增。
**W2 代价模型受害者选择（缓存侧）**：衰减复用计数 + 深度次级键，运行时可观测。
**W3 复杂度门禁**：窗口外退回 LRU（零开销），窗口内启用 W2；禁止块级树结构作信号（实测分支度 0.001–0.002）。

## 失败清单（全部写进论文）

- F-SIEVE 扇出代价：conv 0.1247 / tool 0.4346 → 输给复用计数。
- DEPTH 深度优先：tool 0.4384，输 LFU-W 0.6%。
- P-SIEVE 二次命中晋升：0.1332 vs SIEVE 0.1337。
- ADAPT 密度切换：conv 贴 SIEVE、syn 退化 0.0480、agentic 完全退化为 LRU。
- 共同病因：子节点 ≥2 的分块占比仅 0.001 / 0.001 / 0.002，块级树信号不存在。
