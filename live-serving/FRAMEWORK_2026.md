# TEW v4：两因子淘汰窗口 —— 面向 2026–2028 的框架（2026-11-24 修订）

取代 v3（W1/W2/W3 + F1/F2/F3）。唯一实质改动：窗口判据从"单标量 σ"改成**两个独立可测因子 + 一个遮蔽因子**，三者是**合取**关系而不是求和。每个断言都由本仓库的测量背书：真机 110 轮（`out/`）＋公开生产 trace 回放（`trace/`、`PrefixSim/`）。

## 三个运行时可观测量

- **σ_cross**：在所有"复用型块访问"中，上一次访问者属于**不同请求流（session）**的比例。衡量缓存是否需要跨租户记忆；session 内复用不算。
- **κ**：容量松弛 = `C / W`，C 为块池，W 为一个复用窗口内触达的 distinct 块。κ<1 表示连一个窗口都装不下，κ>1 表示受害者选择才有余量可花。
- **π**：被钉住比例，即到达请求自身已持有（refcount>0、永不为候选）的块占比。π→1 时策略对分配器是**不可见的**。

## 定律

    Δ(policy) = F(σ_cross, κ) · (1 − π)

Δ 为相对 LRU 的命中率增益。F 对两个自变量都单调递增，且在各自两端归零：σ_cross→0 时没有可复用内容；κ→0 时两种策略同样饥饿；π→1 时分配器根本不询问策略。**窗口**是三量都处于中段的区域——它比淘汰算法文献默认的区域窄得多。

## 证据

| 来源 | σ_cross | κ | π | Δ(SIEVE−LRU) |
|---|---|---|---|---|
| 真机 synthetic | 复用几乎全为跨血缘，但只深 1 块 | 低（命中 5.1%） | 0 | −4.5% |
| 真机 conversation | **0.995**（99.5% 复用跨 session） | 中（1733 blocks，命中 10.7%） | 0 | **+24.6%** |
| 真机 toolagent | 0.41 | 中 | 低 | +1.9% |
| 真机 agentic | 结构上 ~1.0（65% 共享） | 中 | **~0.65** | −0.6% |
| 真机 conversation @400 blocks | 0.995 | **0.023** | 0 | +2.6% |
| **生产 trace A @64k blocks**（freeinference，327,548 请求、656,240,179 块访问、222,934 session） | **0.160**（83% 复用同 session） | 高（命中 91.75%） | 0 | **+0.014 pp** |
| 生产 trace A @256k / @1M blocks | 同上 | 更高（93.62% / 93.81%） | 0 | +0.011 pp / +0.011 pp |
| 生产 trace A，S3FIFO @64k | 同上 | 同上 | 0 | **−0.57 pp** |
| **生产 trace B @64k**（chutes，515,817 请求、603,642,254 块访问、402,221 session） | **0.496**（65% 复用跨 session，间隔 7218 s） | 低（命中 72.69%，池仅覆盖 0.05% 地址空间） | 0 | **−1.70 pp** |
| 生产 trace B，S3FIFO @64k | 同上 | 同上 | 0 | **−4.22 pp** |

三条生产读数解释了 2026 年文献的分裂：Harvard 的 trace 研究（arXiv:2609.28870）说"花哨淘汰在生产流量上失效"，我们在真机上测到 SIEVE 领先 LRU 24.6%。两者都对，差别是**哪个因子在起作用**：他们的 agent 流量 session 内局部（σ_cross=0.16），recency 已把几乎全部复用吃掉；他们的 chat 流量虽然跨 session（0.496），但 64k 池只覆盖 139.5M 地址空间的 0.05%，跨 session 复用根本落不进缓存。我们的 conversation 同时满足两条：σ_cross=0.995，且 1733 blocks 覆盖整个复用窗口——所以只有在"跨流 + 池够覆盖复用窗口"这个合取里，淘汰策略才有 24.6% 的空间。

**由此得到的可执行判据（不是修辞）**：部署侧先算 σ_cross 与"池/复用窗口"之比；两者都在中段才启用复用计数策略，否则一律 LRU，且不要引入任何树结构信号。

## 对 2026–2028 的推论

**2026 — 报告口径。** 任何淘汰结论必须同时报 σ_cross、κ、π，否则数字不可迁移。这三个量已可由引擎自身计数器机械算出：请求上的 session id、命中路径上的复用计数、候选块的 refcount，无需额外硬件。本仓库 `sigma_trace` 从离线 trace 算，`policies.py` 在真机上算。

**2027 — 要路由器，不要新策略；但路由器必须住在调度器。** Δ 在窗口外为 0、窗口内 +25%，所以**条件控制器**优于任何单一策略：每窗口用计数器估 σ_cross 与 κ，窗口外走 LRU，窗口内走复用计数策略。这是"策略选择算法"而非新淘汰器，且可作为 2×2 表（路由器 vs 其自身组件）在同一台机器上检验。我们按"复用但陈旧"的代理量在分配器内部实现过一版（`tew`）：三个负载上代理量 0.006–0.085，从未过阈，退化为 LRU——因为跨 session 复用在真实负载里常常是**高频浅层**（许多 session 同时命中同一 system prompt），既不陈旧也不孤立。同一个回放里真正能分开三种负载的量是"命中落在前 5 块的占比"（0.44/0.50/0.24），而它需要"匹配前缀深度 + session 身份"，两者都在调度器侧。结论：2027 的选择器必须做成调度器侧组件，淘汰器内部无从估计。生产 trace 上的预期收益约 0（σ_cross=0.16）；收益在跨租户、工具密集、agent 密集部署——正是 2027 流量走向。

**2028 — 因子消失。** disaggregated prefill/decode 下，块池不再是复用丢失的唯一位置：路由决定请求是否还能遇到自己的前缀。此时单机内部淘汰退为二阶项，Δ 塌缩，除非放置与前缀亲和绑定。框架结论：2027 之后不要再优化淘汰器，优化 σ_cross 感知的放置，淘汰器只作为窗口内兜底。

## 可证伪点（每条都有可跑的检验）

1. **合取**——构造 σ_cross 高但 κ 低的负载（synthetic 即是）：若某策略在那里取胜，合取错误。实测 −4.5%。
2. **κ 单调**——400→1733 blocks 扫描必须单调（+2.6%/+0.3%/+6.6%/+24.6%）；若某策略 400 胜、1733 负，则定律错误。
3. **π 不可见**——agentic（π≈0.65）跨度必须 <1%：实测 0.8%。
4. **生产可迁移**——若某策略在两条生产 trace 上都取胜，则定律错误：实测 A（σ=0.160）+0.014 pp、B（σ=0.496）−1.70 pp，S3FIFO 在 B 上 −4.22 pp。成立。
5. **σ 单独不足**——chutes 的 σ_cross=0.496（跨 session 64.5%），若策略在该 trace 上取胜，说明 κ 不是必需条件；实测 SIEVE 反输 1.70 pp，说明"池覆盖复用窗口"确实是独立条件。

## 边界

单模型 1.5B、单卡 12 GB（与他人共享）、block=16、并发 8/16/32；生产 trace 为离线回放（无 refcount、无 live 集），因此 π 在 trace 侧恒为 0，两侧的 π 不同源。不影响方向性结论，但 κ 的具体数值两侧不可直接比较（trace 侧用块体积比近似）。
