## 创新 1（2026，算法）：带衰减的运行时复用计数受害者选择（LFU-W）

**问题**。淘汰器传统上只能看“最近访问时间”（LRU）或“插入顺序 + 一个 visited 位”（SIEVE）。这两类信号对前缀缓存的真实复用结构是错的：前缀是**跨请求存在**的，一次块被复用的次数在线可得，但从未被当作受害者代价用。

**算法**。在分配器命中路径上 `note_access(hash)` 记 `cnt`；受害者代价取 `cnt`（升序选最小），`cnt` 每 256 次淘汰整体减半；深度作 tie-break。两处改动，不引入任何树结构。

**为什么不是增量**。它不是“LFU 换个淘汰器”：滑动窗口式衰减使“早期热块”不能长期占位（纯 LFU 的固有失效模式），而计数器在引擎里本来就被命中路径更新，成本为零。实测它在四负载均值上领先所有结构感知变体（0.3157 vs SIEVE 0.3104、DEPTH 0.3151、LRU 0.3033），在 toolagent 上是全场最优（0.4409，+5.8% over LRU），在 SIEVE 最好的 conversation 上只输 1.7%。

**代价可控**。全扫描换成 k=16 采样：conversation 命中率 −2.1 个点，换 +14% 吞吐与 p50 从 122 ms 降到 103 ms；toolagent 只 −0.5 个点换 +6% 吞吐。这把“精度换延迟”变成一个显式调度旋钮，而不是实现副作用。

## 创新 2（2026，框架）：TEW 窗口——三条可观测必要条件

**框架**。任何淘汰结论必须同时报三个量，否则不可迁移：

- **σ_cross**：复用访问中跨 session 的份额（单机 conversation 0.995、toolagent 0.41；生产 freeinference 0.1699、chutes 0.6451）。
- **池占用命中率**：命中率 ≥0.9 时没有可赚的东西（freeinference 0.918 → +0.014 pp）。
- **π**：被 refcount 钉住、永不进候选集的块占比（agentic π≈0.65 → 四策略跨度 0.8%）。

再叠加一个**符号级**条件：复用深度（synthetic 跨流但只深 1 块 → −4.5%）。

**边界（必须一起读）**。它只给必要条件，不给充分条件。chutes @64k 三条全过（0.645 / 0.942 / 0.727，重访集中度 47.8% 落在 >32 次块上）仍输 1.70 pp，4× 池后只剩 0.16 pp。我们不拟合故事，只列两个可分辨假设：H1 单请求链 ≈1,170 块对 65k 池的结构性劣势；H2 回放把 π 固定为 0，真实部署并发可能很高。

## 创新 3（2027，算法）：调度器侧选择器 SEW（Scheduler-side Eviction Window）

**关键否定**。先在分配器内部做估计（`tew`）：用“复用但陈旧”作 σ 的代理，三个真机负载上代理量 0.006–0.085，从未过阈 → 退化成 LRU。诊断：真实跨流复用的特征是**高频浅层**（多 session 同时命中同一 system prompt），既不陈旧也不孤立。**所以 σ 不可能在受害者集合内部被估计。**

**算法**（前端估计 + 分配器执行，256 请求一个窗口）：

```
每窗口维护:
  lineage(r) = argmax_{k in [i-64,i)} lcp(r, k)  if lcp >= 4 else new
  sigma_hat = cross_reuse / all_reuse
  lambda_hat = new_blocks / window,  g_hat = mean cross gap (requests),  rho_hat = C / (lambda_hat*g_hat)
每窗口末:  policy <- SIEVE if sigma_hat >= 0.25 and rho_hat >= 0.40 else LRU
分配器侧: 仅切换受害者规则, 无新数据结构, 无新 API
```

**实测（本地三 trace × 四容量 = 12 个工作点，无未来信息、阈值先验写定未调参）**：

- 工作点 1733 blocks：**0.1121 vs LRU 0.0980（+14.4% 相对）**，可达增量 2.49 pp 中拿到 **1.41 pp（57%）**；
- **0 个负窗口**（400 blocks 时 SIEVE 本来只值 +0.27 pp，选择器正确留在 LRU）；
- 事后最优 0.1277，regret 1.56 pp，其中主体是“动作集只有 SIEVE”（800/1200 上 LFU-W 更强却没切过去）——这是明确的下一个动作，不是隐藏的失败。

**为什么它比“更好的淘汰器”更前沿**。2026 年的文献在争论哪个淘汰器赢；这里证明的是**赢的条件可测、且测量点必须在调度器侧**。这条结论可迁移到任何 prefix-cache 实现，而不是某次调参的产物。

## 创新 4（2028，框架）：从“淘汰”转向“放置”的可测判据

disaggregated prefill/decode 下，块池不再是复用丢失的唯一位置：路由决定请求还能不能遇到自己的前缀。可测判据：一个窗口内 `refcount>0` 块的体积占 C 的比例——若它已过半，任何单机淘汰器都是二阶项（agentic 的 0.8% 跨度就是该判据的单机版证据）。2028 的动作因此是“σ 感知的放置 + 窗口内淘汰兜底”。

## 可证伪（每条都有对应实验）

1. 命中率 ≥0.9 时任何策略对差 ≤0.02 pp：freeinference 实测 +0.014 pp。
2. π ≥0.6 时跨度 <1%：agentic 0.8%。
3. σ_cross ≤0.2 时增益 ≈0：freeinference 0.1699 → +0.014 pp。
4. 复用深度 ≤2 块时增益为负：synthetic −4.5%。
5. 池放大 4×，负向 trace 输幅单调收缩：chutes −1.70 → −0.16 pp。
6. 选择器不得在任何窗口负收益：12 个工作点实测 0 个。
